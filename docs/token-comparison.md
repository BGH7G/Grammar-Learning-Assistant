# Token 对比与提示词备份

最终同条件实验：[完整报告](benchmarks/v1-v2-1792834220/summary.md)、[原始 JSON](benchmarks/v1-v2-1792834220/report.json)、[逐次 CSV](benchmarks/v1-v2-1792834220/summary.csv)。

条件：同一 DeepSeek 模型、温度 0.3、思考关闭、JSON mode 沿用同一配置、输出上限统一 8,192 Token；六条公开句子各两轮，交替执行条件顺序。修复重试计入成本。

| 条件（12 次累计） | 输入 | 输出 | 总 Token | 平均耗时 |
| --- | ---: | ---: | ---: | ---: |
| v1 整句完整解析 | 6,772 | 4,036 | 10,808 | 2.11 秒 |
| v2 首屏一层 | 7,406 | 1,425 | 8,831 | 1.50 秒 |
| v2 按标记展开至四层，含首屏 | 48,153 | 6,829 | 54,982 | 8.75 秒 |

v2 首屏：输出减少约 64.7%，总 Token 减少约 18.3%，平均首屏时间减少约 29.1%。输入增加约 9.4%；全部展开的累计 Token 约为 v1 的 5.09 倍。因此默认按点击展开，并利用会话缓存；缓存回访新增模型 Token 为 0。首屏与完整分析工作量不同，不将两者视为同等深度的语法质量对比。

首层结构校验两版均为 12/12 无修复通过。v2 深层遍历全部完成，包含 4 次修复请求；服务未返回推理 Token，不推断为零。抽查发现个别连接词标注错误，已在完整报告明确列出。格式有效不代表语法全对；六条句子不能证明长期达到 95% 的目标。
