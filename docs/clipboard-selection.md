# 剪贴板取词

## 当前行为

在“热键”页面录入并保存划词翻译快捷键，默认 Ctrl+Alt+E。启动时注册已保存热键，保存修改时先注册新键，冲突则保留原键；配置写入失败时尝试回滚注册。热键单独存储于应用配置目录的 hotkeys.json，不涉及模型设置或凭据。

在其他软件选中文字后触发热键。后台单个工作线程等待修饰键自然松开，再检查目标窗口并用 SendInput 发送 Ctrl+C。仅在剪贴板序列号更新、短暂稳定且所有者进程符合目标时读取 Unicode 文本。支持伴随富文本和浏览器注册格式，不备份、清空或恢复原剪贴板。剪贴板保留目标应用本次复制结果。

文本最多 2,000 Unicode 字符，保留首尾空格和换行。取词结果只预填到分析页；当前存在不同的未提交输入时，显示“替换输入 / 保留当前输入”。模型分析仍由用户点击现有按钮触发。

事件仅通知状态更新，Rust 保留最新状态；前端监听后主动查询并在窗口重新获得焦点时补查，使用修订号及请求 ID 防止乱序、重复预填。取词串行执行，忙碌时拒绝额外请求。退出时等待当前事务结束。

## 已知限制（2026-10-27 检查）

1. 重复取相同原文仍会清除当前解析视图，需要重新点击分析。
2. 仅禁止将 Ctrl+C 配置为取词热键；Ctrl+V、Ctrl+X 等常用编辑键仍可能被用户配置并影响其他应用。
3. 修饰键等待和复制观察预算各为 800ms，剪贴板锁重试最多 300ms；这不是整个事务的硬超时。GetClipboardData 的延迟渲染可使工作线程等待更久，期间取词保持 busy，退出也可能等待。
4. 所有者进程必须与前台目标一致；辅助进程或剪贴板代理场景可能误拒绝合法复制。相同目标进程中的另一次复制仍不能仅靠序列号和所有者绝对区分。
5. 不验证控件是否确有选区，部分编辑器在没有选区时会复制整行；因此应核对原文后再点击分析。
6. 不涉及 UIA、OCR、鼠标自动划词、悬浮窗或自动模型分析。高权限窗口及禁止复制的内容可能失败，保留手动粘贴入口。
