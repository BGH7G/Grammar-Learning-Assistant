# 段落阅读与单一解析抽屉（2026-10-26）

本版按第二版设计实现：提交原文后，先展示整段英文和逐句对应的中文，不自动展开语法。点击原文或译文中的句子，只更新下方同一个解析抽屉。

## 布局与交互

- 上区默认约占可用阅读空间的 40%，下区始终保留给抽屉；原文和译文各自在上区内部滚动，避免小窗口只看到英文而完全看不到中文。
- 句子带小号序号与状态点；浅色表示悬停/焦点，较深背景和底线表示选中。两种语言双向联动，停留后将对应句滚动到另一语言的可见范围。
- 悬停或焦点停留 300ms 后展示主干提示并优先处理该句；快速划过会取消等待任务。
- 抽屉头部保留句号计数、主干、上一句、下一句和关闭按钮。切换内容时不会新增抽屉。
- 切换句子只重置抽屉内部的滚动位置，原文区域和整个页面不跳动。
- Tab 定位句子、Enter/Space 打开；抽屉内 ↑↓/←→ 切换句子，Esc 关闭并回到原句。内部成分通过点击和面包屑继续下钻；抽屉模式不再让左右键同时承担成分切换。
- 分隔线支持鼠标、触摸拖动及键盘上下微调。默认 40%，最多 65%；最小比例随窗口高度调整，优先为原文与译文保留约 170px 空间（极矮窗口另行限制）。
- 失败句保留错误状态，点击后可在抽屉重试；显式重试只处理该句，不重新请求整个段落。

## 请求与缓存

`prepare_analysis` 只做配置核对、本地无损切片/分句和会话创建，不调用模型。前端收到空层文档后逐句加载译文，复用 `expand_node` 请求每个根节点的第一层结果。

因为完整译文本身需要每句的第一层结果，提交后会正常排队加载全部句子的首层，最多两路并发；悬停/点击只调整队列优先级。快速划过不会额外发起请求，也不会阻止原本为译文排队的首层加载。相同句子的悬停、点击、译文与语法展示共用一个请求和缓存，不另外请求翻译或主干。没有预取更深的语法层。

前端队列阻止在途与已缓存任务重复执行；组件销毁时停止尚未开始的任务并忽略旧结果。React StrictMode 的效果清理也不会触发尚未开始的请求。已发出的服务请求无法保证撤回。后端继续执行会话指纹、在途去重、48 层预算、配置失效保护和最多一次结构修复。单词根节点允许首层解析，普通终端单词仍不可继续展开。

原文或模型配置变化后，旧会话与指标不能覆盖新结果。切换设置页时已加载的根层及内部结构保存在当前前端文档中；关闭抽屉不清除这些结果。当前提示词与上一轮 Token 优化保持一致，仍为 `layer-v2.10.5-compact`。

## 验证

- 前端 TypeScript/Vite 正式构建通过。
- Rust：32 项本地测试通过，8 项在线测试默认跳过；Clippy 所有 targets、警告视为错误通过。
- `node scripts/check-component-labels.mjs`：原有成分/类型标签检查通过。
- `node scripts/check-paragraph-workflow.mjs`：两路并发、缓存、优先级、失败后显式重试、清理与旧结果隔离、300ms 意图延迟、七句离线数据的无损映射/层级/覆盖检查通过。
- 模拟服务 UI 检查：7 句初次共 7 次请求；打开失败句不增加调用，按“重试本句”后共 8 次。加载状态、占位译文和错误入口可见。
- 正式构建在默认窗口、1600×900 和 640×720 复核；宽窗口阅读区 256.64 / 641.63px，约 40%；窄窗口拖动后最小阅读区 170px。两种尺寸均只有一个可见抽屉，无页面横向溢出。
- 已验证句 2 → 句 3 的内容替换、原译文同时选中、内部结构、Enter 打开、方向键切句与 Esc 返回原文焦点。
- 最终构建实测抽屉内部滚动位置为 169px，切换句子后归零；结果见 `scroll-switch-check.json`。焦点停留后的主干提示与另一已选中句可同时存在。

截图使用七句离线固定示例，模拟状态测试也未访问真实模型。本轮没有重新测试模型语法准确率，也没有重新执行产生 API 用量的 Token 基准；新增后端命令、缓存路径通过编译和本地回归验证，尚未进行桌面安装包发布。
